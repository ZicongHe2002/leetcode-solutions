# 801. Minimum Swaps To Make Sequences Increasing · Python

[原题](https://leetcode.com/problems/minimum-swaps-to-make-sequences-increasing/)。

原题两个数组等长2..100000，每项0..200000，保证存在解。一次只能交换同下标两数组元素，目标使两数组分别严格递增并最小化交换下标数。输入保持；不定义原题保证之外的无解返回值。

处理到i后，keep是第i项不交换的最小成本，swap是第i项交换的最小成本，两状态都要求两个前缀已严格递增。初始keep=0、swap=1。相邻原位置两数组各自严格递增时，前后同交换状态可接，更新新keep自旧keep、新swap自旧swap+1。两条交叉比较也严格递增时，前后不同状态可接，新keep自旧swap、新swap自旧keep+1。两个条件可同时成立，必须分别取最小，不能用else互斥。

每个合法前缀只需记最后位置是否交换，因为更早位置已由前缀条件保证；两种转移穷尽前后四种交换组合。使用新变量同时替换，避免第二条转移读到本轮刚更新的成本。size+1大于任一可行成本，作为不可达状态哨兵；不可能状态不会优于保证存在的最终解。

每下标常数比较与更新，时间O(n)，额外空间O(1)。严格小于保证相等不能错误地当递增；不实际交换输入，也不保留完整DP表。

独立oracle枚举全部交换掩码，真实构造两个交换后数组，再逐相邻检查严格递增，取最少1位数。值0..3、长度2..4全部69888对候选中，对每个可解输入核对，保证之外的无解只由oracle筛出而不调用接口。另测官方例和100000长度强制整段同向案例：每列为i与i+1，相邻等值阻止交换状态变换，故仅两种全局方向可行，最优恰为已翻转列数与其补数的较小者。核对int及两个输入保持，未向LeetCode提交。
