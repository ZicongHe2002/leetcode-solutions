# 483. Smallest Good Base · Python

[原题](https://leetcode.com/problems/smallest-good-base/)。

输入十进制字符串n，找最小的整数进制k>=2，使n在k进制下的全部数位都是1，返回k的十进制字符串。原题n在3..1000000000000000000且无前导0；输入合同外的非数值不在本实现范围。

若有e+1个1，则n=1+k+...+k^e。k>=2限制e<=floor(log2 n)，用bit_length-1精确取得这个上限。对相同n，更长的全1表示必须用更小进制：若位数增加而进制不减，几何和严格增加。因此按e从大到小搜索，第一组解就是最小进制。最后两位11永远可用k=n-1表示，作为保底。

固定e>=2时，几何和随k严格递增，可整数二分。令b=n.bit_length()，n<2^b；任何解满足k^e<=n，故k<2^(b/e)。用2^ceil(b/e)作为包含所有解的整数上界，只用加法、整除和移位，不依赖浮点开根在10^18附近的舍入。二分从2开始，比较后缩小相应端点。

几何和用Horner形式从1开始反复total=total*k+1，共e步；超过n即可提前结束，因为剩余项只会让总和更大。相等才接受，不能把近似幂或整除关系当成完整全1表示。Python整数保存精确中间值，没有浮点误差或固定64位乘法溢出。

按整数运算次数给出保守上界：O(log n)个指数，每个至多O(log n)次二分，每次至多O(log n)次乘加，总O((log n)^3)，仅固定数量整数状态，O(1)辅助空间；若按任意精度位操作计费，还需计入整数乘法成本，原题输入至多60位。

独立参考按k从2递增，反复对n除k，验证每次余数都为1，不使用几何和或指数二分；n=3..3000的2998个数核对最小性。另测接近上界的二进制全1、三进制38位全1（为偶数故不可能是二进制全1）、原题10^18示例与13/4681，逐项用除余回读实际进制数位。未向LeetCode提交。
