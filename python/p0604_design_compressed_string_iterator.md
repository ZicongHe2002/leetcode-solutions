# 604. Design Compressed String Iterator · Python

[原题](https://leetcode.com/problems/design-compressed-string-iterator/)。

实现平台StringIterator类。合法compressedString由英文字母和后续正整数计数组成，编码长最多1000，每段计数1..10^9；最多100次客户端next/hasNext调用。next有剩余字符时返回一个字符，否则返回单个空格；hasNext返回bool，不消费字符。大小写区分，相邻同字母的两个编码段也可顺序读取。不扩展为无计数、0计数或任意损坏编码的解析器。

compressed保存输入引用，index指向尚未解析的下一段字母或串尾。current和remaining表示已经解析的当前段还有多少字符可取。next先确认有剩余；若当前段耗尽，就读取下一字母及它后面的全部数字，得到完整计数，再减1并返回该字母。一次只加载需要用到的段，不把十亿重复展开，也不预存全部段数组。

hasNext只检查remaining>0或index尚未到编码末尾。计数保证为正，因此只要有未解析的合法段就必有字符；不需要为了回答这个问题而移动index。最后一段解析后index可以已在串尾，但remaining仍正，必须继续返回真；只有两者都耗尽才返回假。耗尽后的next直接返回空格，不再减成负数或访问越界。

构造O(1)，hasNext为O(1)。next通常O(1)，加载新段时花O(d)读取d个计数数字。q次next累计时间O(q+P)，P为实际解析的编码前缀长度，每个编码字符最多读一次；计数最大10^9至多10位，本题单次加载也有常数上界。除已有输入字符串引用外只用常数个有界字段，额外空间O(1)，不与展开长度成正比。

独立小规模参考用正则解析并直接展开字符串，逐字符比较next，在每个字符前重复hasNext验证不消费，耗尽后重复验证空格和False。两字母、计数1..3的1..4段全部1554种编码，逐实例客户端调用不超过100。另测多位计数、相邻同字母段、1000字符编码的100次混合调用，以及10^9重复段的100次调用；大计数参考不展开，未测十亿次完整耗尽，也未做计时或内存基准。未向LeetCode提交。
