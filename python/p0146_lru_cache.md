# 146. LRU Cache · Python

[原题](https://leetcode.com/problems/lru-cache/)。

原题接口LRUCache(capacity)、get(key)、put(key,value)。容量1..3000，key为0..10000，value为0..100000，get/put总共至多200000次。get未命中返回-1，命中和写入都把该键变为最近使用；超容量淘汰最久未使用键。put返回None。

哈希表保存键到节点的定位，双向链表从旧到新维护使用顺序。两个哨兵只表示边界，不进入键表。命中get或更新put时摘下同一节点，再接到最近端；新键先创建并接到最近端，只有数量超容量才从最旧端摘除，并同步删除哈希表键。更新已有键不增加数量，也不应淘汰其他键。实际值0和键0都有效，未命中通过节点是否存在判断。

哈希定位平均O(1)，每次链表重接固定指针数，get/put平均O(1)，存储O(capacity)。没有使用排序、线性查找或库自带LRU实现。

独立oracle使用OrderedDict的移动及首端弹出，不复用节点链表。容量1..3、9种读写动作、长度0..4共22143个短程序核对，包括更新、读命中与读缺失。最大容量3000再运行200000次合法get/put，键覆盖10000且值含0与100000，每次get与独立模型比较；验证返回类型和put的None。
