# 591. Tag Validator · Python

[原题](https://leetcode.com/problems/tag-validator/)。

code长度1..500，仅含题目规定的英文字母、数字和标点。整个字符串必须恰被一个完整根标签包围；标签名为1..9个ASCII大写字母，起止名相同且嵌套平衡。内容可包含其他完整标签、普通字符和CDATA；普通内容不能出现未匹配的`<`。CDATA以`<![CDATA[`开头，到首次后续`]]>`结束，内部任何字符均不解析。空串额外定义为False，不按通用XML的属性、自闭合标签或转义规则扩展合同。

index单向扫描，stack保存尚未关闭的合法标签名。遇开始标签，找到下一个`>`，核对名称长度和每个字符后压栈；遇结束标签，名称必须等于栈顶才弹出。结束名匹配已验证的开始名，因此不必再独立校验同一名称。非`<`字符只有在栈非空时才能作为内容出现。

CDATA分支先于普通开始标签，只允许在已有标签内，直接find首次`]]>`并跳过全部原文，所以内部的`<`、`</A>`和看似另一个CDATA前缀都不会改变标签栈。找不到结束符立即无效。CDATA之外的`]]>`只是普通字符，无须单独禁止。非CDATA的`<!`开头将按标签名规则拒绝。

初始位置必须打开根，根关闭后若还有任意字符，下一轮“非初始位置且栈空”就拒绝，避免两个根或根后空格被接受。最终栈必须空，拒绝未关闭标签。这个条件与栈顶匹配共同保证恰好一个完整根及正确嵌套，不会把只统计开始/结束数量当成正确。

扫描、有限前缀判断、标签名称切片以及标签/CDATA结束位置查找的总成本为O(N)，时间O(N)。栈只保存当前深度H个已验证的合法名称，每个名称最多9字符，栈空间O(H)。开始和结束标签分支都先切出名称再校验；非法输入的名称可能长达O(N)，即使H为常数，临时切片仍可能占用O(N)空间。因此总辅助空间为O(N)。不使用浮点、外部解析器或输入改写。

独立参考先用正则词法分析提取CDATA、合法起止标签和普通文本，检查所有字符都被连续消费，再用递归元素语法验证单个根及嵌套。穷举字母表`<`、`>`、`/`、`A`、`x`的0..7长度97656个字符串；另生成273个合法片段并逐字符删除作变异对照，删除后不预设必然错误。边界单列CDATA首终止符、CDATA外的`]]>`、错配/并列根、9/10字符名、500字符输入和497字符深嵌套。未向LeetCode提交。
