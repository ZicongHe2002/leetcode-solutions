# 464. Can I Win · Python

[原题](https://leetcode.com/problems/can-i-win/)。

两人轮流从1..M选择一个此前没选过的数，加到共享总和，谁先使总和至少为T谁赢，判断先手能否在最优对弈下必胜。原题M在1..20，T在0..300。T<=0视为先手已经达到目标；全部可选数之和仍小于T时双方都无法达到，返回False。

used位掩码表示双方已经拿走的数字，remaining是达到目标还差的数值。对当前行动者，存在一个未用选择能立即达到目标，或者能让对方落入必败状态，就为必胜；若每个合法选择都会把对方送入必胜状态，当前就必败。这完整枚举双方最优决策，不把最大数贪心当成策略证明。

remaining由T减去used中所有数字之和唯一决定，选择顺序不影响它；行动轮次也由已选个数决定。因此缓存只按used键，不会混合不同目标或不同回合状态。每次调用创建新memo，递归只增加一个已选位，最多M层，不会循环。首次判断总和不足避免把根本无人能获胜的局面按最后一手错误计为胜利。

最多2^M种已选集合，每状态检查M种选择，时间O(M*2^M)，缓存O(2^M)，控制栈O(M)。从较大选择开始只影响搜索顺序，不能取代对所有必要分支的判断。

独立参考直接保存剩余可选数元组和累计总和，递归展开原始游戏树，不使用位掩码或记忆化。M=1..7、T=0..总和+1全部98组核对，含已经达到和总和不足。另测M=20、T=300、一步获胜、补成21的后手策略及T=210必须取完20数的后手获胜边界；同一Solution多次调用核对缓存不泄漏。未向LeetCode提交。
