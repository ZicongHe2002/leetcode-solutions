# 651. 4 Keys Keyboard · Python

[原题](https://leetcode.com/problems/4-keys-keyboard/)。

原题有A、Ctrl-A全选、Ctrl-C复制选择、Ctrl-V追加剪贴板四种按键，求最多n次按键能打印的最大A数，1<=n<=50。屏幕初始为空。全选加复制共两步，不能按2 Keys Keyboard的一步Copy All计费。剩余预算可继续按A，因此最多n步的最优值也可在恰n步内取得。

令best[i]为i步预算内的最优屏幕数。若最后按A，候选为best[i-1]+1。其他有用方案可整理成：先在b步内生成best[b]个A，再全选、复制，最后连续粘贴i-b-2次，得到best[b]*(i-b-1)。在最后一次有效复制之后若还夹杂A，可把这些A移到复制之前：原有屏幕不会减少，之后每次粘贴还可多包含这些A，故不会更差；多余全选或复制可删去。因此这个最终复制段与最后按A的情况覆盖最优方案。

枚举b=1..i-3，确保至少一次粘贴；b=0复制空屏无收益，只有全选/复制而不粘贴也不优于继续按A。DP从小预算递增，时间O(n²)、额外空间O(n)，全程整数，不用近似增长率或固定只试某几个乘数。

独立小输入oracle直接枚举四种按键后的(屏幕数,剪贴板数,选择数)状态，按键A或追加粘贴后取消选择，Ctrl-A选择全屏，Ctrl-C复制非空选择；核对预算1..12，不使用复制断点公式。另一oracle把全选+复制作为成本2的动作，在(屏幕数,剪贴板数)状态图上按预算搜索，只按分量优势删去被支配状态；A、Paste、Copy All两步动作都保持这种优势，故剪枝不删除更优结果。对照全部1..50预算，最大预算也由实际搜索获得，不预填答案。未向LeetCode提交。
