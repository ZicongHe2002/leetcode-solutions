# 460. LFU Cache · Python

[原题](https://leetcode.com/problems/lfu-cache/)。

实现LFUCache(capacity)、get和put，容量满时淘汰访问频率最小的键，频率并列则淘汰最近最少使用者。新键频率为1，成功get与更新已有键的put都加1，失败get不创建键。原题容量1..10000，key为0..100000，value为0..10^9，单实例最多200000次get/put；本实现额外支持0容量，忽略put并让get返回-1。

entries保存每键的值和频率；buckets把相同频率的键放进OrderedDict，左侧最旧、右侧最新。每次成功访问把键从旧桶移到频率+1桶末尾，同时更新值；同频键的入桶顺序等于最近一次访问顺序，因此桶首正是该频率下应淘汰的LRU键。更新已有键不是新插入，不应先淘汰别的键。

minimum记录当前最小频率。访问导致最小桶变空时，刚访问的键一定进入旧频率+1桶，所以最小频率恰好加1，无需搜索全部桶。新键插入后最小频率重置为1；满容量时只从minimum桶首弹出。空桶立即删除，避免长期访问同一键时积累历史频率桶。

所有get/put只进行固定数量字典与OrderedDict查找、删除、追加或首项弹出，平均时间O(1)，没有扫描全部键找最小频率。条目与非空桶总量O(capacity)，辅助空间O(capacity)。频率可随访问次数增大，Python整数精确保存；键0和值0按成员资格处理，不用真假值判断是否存在。

独立参考只保存值/频率/逻辑时间戳，淘汰时线性扫描全键的(频率,时间)，不使用频率桶。容量0..3、五种get/put动作、长度0..6全部78124段程序逐步核对公开返回和模型状态，并检查最小频率、桶内LRU顺序及无空桶；0容量为扩展。另测确定种子随机更新、10000容量、键值边界，以及容量1恰好200000次调用后仍只有一个频率桶。未向LeetCode提交。
