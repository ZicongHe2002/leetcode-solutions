# 88. Merge Sorted Array · Python

[原题](https://leetcode.com/problems/merge-sorted-array/)给nums1预留m+n个位置，其中前m项有效，nums2含n项；两个有效部分都非递减。`Solution.merge`将结果写回nums1并返回None，不替换原对象，也不修改nums2。两个输入缓冲区互不别名；占位零不属于nums1的有效数据。

left与right指向两个未处理部分的末尾，write指向结果的最右空位。每次选较大的末尾值写入write，再推进对应指针和write。从右侧写可避免覆盖nums1尚未读取的数据；相等时选nums2，仍保证输出有序。

循环不变量是write之后的后缀已经等于排序结果的相应最大元素；未消耗的nums1前缀仍保留原值。当nums2耗尽后，nums1的剩余前缀本就在正确位置，无需再复制。只要nums2还有元素，write就严格大于left，因此接入nums2也不会覆盖未读的nums1值。

最坏时间O(m+n)，额外空间O(1)，不先拼接、排序或切片复制。m=0和n=0分别自然处理；两个数组都为空是接口扩展。测试枚举值−1至1、有效长度0至4的35种非递减数组的1225个输入对，用独立排序作期望，检查原地结果、nums1身份、返回None与nums2不变。实际运行结果见PR；没有LeetCode Accepted记录。A实现，OpenAI Codex辅助整理。

## B补写：后向合并状态与覆盖证明

令nums1为`[-2,1,4,0,0,0]`、m=3，nums2为`[-3,1,5]`、n=3。每行列出的指针均为本轮开始时的值，“确定后缀”是本轮写入后的已完成部分。

| left | right | write | 选择来源和值 | 确定后缀 |
| --- | --- | --- | --- | --- |
| 2 | 2 | 5 | nums2的5 | `[5]` |
| 2 | 1 | 4 | nums1的4 | `[4,5]` |
| 1 | 1 | 3 | 相等，取nums2的1 | `[1,4,5]` |
| 1 | 0 | 2 | nums1的1 | `[1,1,4,5]` |
| 0 | 0 | 1 | nums1的-2 | `[-2,1,1,4,5]` |
| -1 | 0 | 0 | nums1已耗尽，取nums2的-3 | `[-3,-2,1,1,4,5]` |

初始化满足`write = left + right + 1`。每轮write减1，同时恰好一个读指针减1，等式始终成立。循环内right>=0，所以write严格大于left，写入只触及nums1尚未读取的前缀之外。取nums1时先读其left位置再写到右边；取nums2时输入缓冲区互不别名，因此也不会破坏nums1或nums2的未读值。

若试图从前向后直接写，例nums1=`[2,3,0]`、m=2，nums2=`[1]`：第一步把1写进nums1[0]会覆盖尚未读出的2；继续按原下标读取便丢失原输入。后向算法使用预留空间避免了这一问题，前向做法必须另备缓冲或移动数据，不能照搬当前空间证明。

当right降到-1时，上述等式变成write=left。剩余nums1[0:left+1]仍是原来的有序前缀，且所有待写位置恰好就是这些位置；已完成后缀是此前选出的最大元素，因此不必把该前缀复制回自身。例如`[1,4,0]`与`[5]`只写入末尾5就已完成。n=0时该理由从初始化起就成立，循环一次也不运行。
