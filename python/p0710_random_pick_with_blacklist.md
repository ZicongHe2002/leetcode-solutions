# 710. Random Pick with Blacklist · Python

[原题](https://leetcode.com/problems/random-pick-with-blacklist/)。

原题n在1..10^9，blacklist含0..min(100000,n-1)个不同的合法值，pick最多20000次。每次必须在[0,n)内所有非黑名单整数中等概率选择，并尽量减少内置随机函数调用。接口为Solution(n,blacklist)/pick；原blacklist顺序和值保持。

设B为黑名单数，M=n-B>0，只在[0,M)内均匀抽一个秩。这个低区间中不在黑名单的值直接保留；落在黑名单的低值一一重定向到[M,n)中未被禁用的高值。高区间共有B个位置，扣掉其中的高黑名单数，恰与低黑名单数相同，因此一定足以配对。

构造时tail从M向右移动，跳过高黑名单，把每个低黑名单映射到当前合法tail，再推进tail。tail单调递增，映射目标互不重复，且所有未映射低值小于M，不会与高目标冲突。最终每个合法返回值对应恰一个秩；内置randrange(M)均匀时，每个合法整数概率恰为1/M。这是双射证明，不是有限随机样本的频率估计。

每次pick只调用一次随机函数，再做一次字典查找，没有拒绝重试。构造时间与存储平均哈希成本下O(B+1)：tail总共最多走过B个高位置，不扫描整个n范围。pick平均时间O(1)、额外工作空间O(1)，n很大而黑名单稀疏时仍只保存黑名单规模数据。

独立测试强制随机源依次返回每个合法秩，直接把结果与[0,n)减黑名单的完整集合比较，同时核对无重复且每次只调用一次随机源。n=1..8的全部502个非全禁黑名单集合及正反输入顺序完整核对，不把确定性秩检查冒充统计实验。另覆盖n=10^9、100000黑名单、单一可用值与20000次pick边界，核对输入保持。未向LeetCode提交。
