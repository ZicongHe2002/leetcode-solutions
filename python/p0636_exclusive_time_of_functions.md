# 636. Exclusive Time of Functions · Python

[原题](https://leetcode.com/problems/exclusive-time-of-functions/)。

原题是单线程、按事件顺序记录的合法调用栈，函数ID为0..n-1、n在1..100，日志2..500条、时间戳0..1000000000。每个start在该时间单位开始，每个end在该单位结束；同一函数可重复调用或递归。不同start不同时发生，不同end不同时发生；调用均配对。实现不更改日志，不为不配对或非法嵌套日志定义恢复行为。

stack保存尚未结束的调用，每个条目是一层调用，递归的相同ID也要重复入栈。previous是当前栈顶尚未记账的第一个时间单位。遇到start(t)，旧栈顶在[previous,t)执行，累加t-previous，再入栈新函数并令previous=t。遇到end(t)，栈顶在[previous,t]执行，累加t-previous+1后出栈，父调用最早从t+1继续，所以previous=t+1。这个+1与下一段起点必须同时处理，才能避免末单位漏算或重算。

空栈时start以前的空闲时间没有函数拥有，不能计入；下一次根调用start会直接重置previous。result按函数ID汇总所有调用层，递归父子间仍只把每个单位记给真实栈顶。日志L条、最大调用深度d，时间O(L+n)，返回数组O(n)，除返回值外工作空间O(d)；不按时间戳上界逐时刻模拟。

测试oracle先直接生成带每个执行单位所属ID的日程，再输出对应嵌套日志；expected由逐单位归属计数得到，不从日志重算区间差。1000个固定种子的合法调用森林含递归与连续根调用，生成时限制节点预算与严格不同的start/end时间。边界检查500条日志、100个函数、一次调用从0执行到1000000000、根调用间的长空闲，以及子调用结束后立即在下一单位开始新调用。实际结果、整数类型与日志保持均核对；未向LeetCode提交。
