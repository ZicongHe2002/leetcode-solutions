# 141. Linked List Cycle · Python

[原题](https://leetcode.com/problems/linked-list-cycle/)判断沿next访问时是否会再次遇到同一个节点。使用`Solution.hasCycle`，不接收题面用于描述环入口的pos参数。文件提供本地`ListNode`；线上可使用题目提供的节点定义。

slow每轮走一步，fast走两步。进入循环前先确认fast及fast.next存在，避免无环链表尾部访问None.next。移动后才比较节点身份，不能把起点时两个指针相等误判为环，也不能根据节点值相等判断。相同值的不同节点仍可能组成无环链表。

无环时fast必然到达None或尾节点。存在环时，两个指针最终都进入环，fast每轮相对slow前进一步；相对位置按环长取模，有限轮内必然相遇。尾部长度为μ、环长为λ时，总时间O(μ+λ)，即O(n)，额外空间O(1)。代码不改节点值或next。

测试使用已访问节点身份集合的独立oracle，覆盖长度0至8、无环及每个合法环入口的全部45种结构，包含自环、两节点环和重复节点值；每次检查所有原next和值都未改变。实际运行结果见PR；没有LeetCode Accepted记录。A实现，OpenAI Codex辅助整理。

## B补写：非环前缀与相对位置

取结构`P0→P1→C0→C1→C2→C0`，非环前缀长2，环长3。节点标签代表身份，值可以全部相同。

| 完成的轮数 | slow | fast | 判断 |
| --- | --- | --- | --- |
| 0 | P0 | P0 | 初始相等不参与判断 |
| 1 | P1 | C0 | 不同节点 |
| 2 | C0 | C2 | 均在环内，相对偏移为2模3 |
| 3 | C1 | C1 | 身份相同，检测到环 |

当slow进入环时fast也已经进入。此后每轮slow前进一步，fast前进两步，fast相对slow的位移增加1模λ。任意起始偏移在至多λ轮内会变为0，故必相遇；进入环前的工作至多与μ成正比，总时间O(μ+λ)。相遇点不必是环入口，检测存在环不能直接当作返回入口的算法。

比较身份至关重要：无环链`X(7)→Y(7)→Z(7)→None`第一轮slow=Y、fast=Z，值相等但身份不同。若用值判断会误报；若在第一次移动前直接比较两个起点，则任何非空无环链也会因同指向head而误报。循环条件保护fast的两步移动；所有操作只读next，原拓扑保持。B补写此逐轮账本和模环长证明。
