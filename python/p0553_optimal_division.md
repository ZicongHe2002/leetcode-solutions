# 553. Optimal Division · Python

[原题](https://leetcode.com/problems/optimal-division/)。

给定1..10个整数，每项2..1000，顺序固定，相邻元素之间都是除法。添加必要括号使值最大，返回表达式文本，不能含冗余括号。所有数严格大于1且为正，是本题简化的关键；输入保持，生产代码不计算近似浮点结果。

任意除法语法树展开后，每个原数都以+1或-1次方参与乘积：右子表达式作为分母会翻转其中所有符号。第一个数沿整棵树的最左路径，总在分子；第二个数在与第一个数首次分开的右子树中又是最左项，因此总在分母。其他数的正负号由括号决定。

由于所有数至少为2，其他每项都放到分子才能取到上界nums[0]*nums[2]*.../nums[1]。表达式a/(b/c/d/...)恰好做到这一点：分母内部的除法按默认左结合，值为b/(c*d*...)，外层再除这个分母后，c及后续所有项都回到分子。因此这不是局部挑选最小分母的猜测，而是达到了所有可能分组的统一上界。

长度1直接返回该数；长度2只返回a/b，不需要括号。长度至少3时，只给整个后缀分母加一对括号。内部左结合本来就是默认顺序，不再加括号；外层这一对不能删除，否则后缀各数都会变成连续相除的分母，因各项大于1而严格降低结果。

令S为输出字符数，数字转换、连接的时间O(S)，辅助和返回文本空间上界O(S)。没有动态规划求解数值或浮点排序，原题固定输入范围下构造规模很小。

独立参考枚举每个切分点和全部二叉括号化，用Fraction精确计算所有可达有理值并取最大。返回文本另用AST只解析整数和除法，核对原叶子顺序、精确值及仅有必要括号，不使用eval或浮点。值2/3/4、长1..6的1092个数组逐一对照；另测长度10、1000端点、多位与不整除情形、原例，核对str与输入保持。未向LeetCode提交。
