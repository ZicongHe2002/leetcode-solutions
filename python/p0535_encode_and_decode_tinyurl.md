# 535. Encode and Decode TinyURL · Python

[原题](https://leetcode.com/problems/encode-and-decode-tinyurl/)。

实现本题Python使用的Codec接口：encode把合法URL变成短URL，decode还原此前由同一对象编码的URL。原URL长1..10000，题目不限制编码规则，也不要求相同原URL每次得到同一短链。这里每次encode分配新标识，所有旧短链在对象生命周期内继续有效；不同Codec实例各自独立。本题是内存对象设计，不调用实际TinyURL网站。

links记录完整短URL到原字符串的映射。假设已经编码K次，字典中就有K个不同键；用K的十六进制表示作为新后缀。非负整数的十六进制表示互异，所以新后缀不会与先前0..K-1的标识冲突，插入后键数增至K+1，不会覆盖旧记录。实现不删除映射，因此直接由len(links)导出下一个标识，不需要另存一份可失配的计数状态。

decode按完整短URL查表，原样返回原字符串，不解析、规范化或再次解码URL。即使原URL本身长得像一个短链，也只还原这一层映射。题目保证decode参数来自同一对象先前的encode；未知短链、跨对象恢复和重启持久化不属于原题保证。

编码标识的字符数是O(log(K+1))，生成后缀及哈希新键的通常时间也在此量级；解码按短URL查表，计入字符串哈希的通常时间上界为O(log(K+1))。没有哈希原长URL或复制其内容，只保留不可变字符串引用。若S是所有保留原URL字符串的总长度，连同保留数据计空间上界O(S+K*log(K+1))；不能把任意长的URL存储一概视为O(K)字节。

测试从返回值出发核对真实往返与长期保留，不依赖具体后缀数字。a/b/c路径长1..5的363个不同URL编码后倒序解码，再重复编码并确认旧短链仍正确。另测10000个不同URL不会冲突、10000字符原URL、查询与片段原样保持、原URL恰为短链形态，以及两个实例状态隔离。实际运行通过，未向LeetCode提交。
