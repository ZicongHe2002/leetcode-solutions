# 690. Employee Importance · Python

[原题](https://leetcode.com/problems/employee-importance/)。

原题employees包含1..2000个员工，唯一ID在1..2000，每个importance为-100..100，subordinates列出合法的直接下属ID，每人至多一个直接领导。查询给定有效员工ID，返回本人及所有直接、间接下属的重要性总和。Employee类由平台提供，使用其id/importance/subordinates字段，不假设数组按ID排序或ID连续。

先建立ID到员工对象的映射，再用显式栈从查询ID开始遍历。首次访问某个ID时，把其重要性计入总和，并把直接下属ID加入栈。seen确保每个可达员工只计一次；它也让遍历不会因重复遇到ID而重复累加。只有通过下属边可达的员工会入栈，无关分支与上级不会被计入。

归纳来看，栈中只包含本人或已确认可达员工的直接下属；每个这样的下属也可达，且继续扩展会穷尽所有间接层级。每个可达员工恰计一次，因此最终和符合题意。负重要性与0按普通整数相加，不能只保留正值，也不能把员工ID当作其重要性。

设N为员工数、E_R为查询可达员工列出的下属边数。建表O(N)，遍历O(N+E_R)上界，平均哈希操作下总时间O(N+E_R)，额外空间O(N+E_R)上界；在原题每人至多一个直接领导的合同下总下属边数O(N)，所以时间和额外空间均为O(N)。员工数组、对象字段与下属列表都只读，使用迭代方式覆盖2000层链，不修改递归限制。

独立oracle反复扫描员工定义，把当前可达集合中员工的下属并入集合，直到闭包不变，再单独求和，不使用栈遍历。按拓扑前序为1..6节点生成873个小森林，三种正负零赋值、每个目标ID共15117次查询，ID使用稀疏值并反排员工表。另覆盖2000节点链和星、负总和与叶子查询，核对员工顺序、字段、下属列表身份和值保持。未向LeetCode提交。
