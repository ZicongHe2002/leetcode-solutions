# 749. Contain Virus · Python

[原题](https://leetcode.com/problems/contain-virus/)。

原题为1..50行列的二值矩阵。每天只能隔离一个连通感染区，必须选下一夜会感染最多不同健康格子的区域；需要选择时保证唯一最大者。其余感染区同时向四邻健康格扩散一层。返回累计墙边数，不能用感染区大小或墙边数代替选区的威胁格子数。

复制矩阵作内部模拟，1为活跃感染，0为健康，-1为已隔离区域。每天先在完全相同的日初快照上迭代遍历所有1连通块。每块保存感染格列表、相邻健康格去重集合frontier，以及感染格到健康格的边数walls。同一个健康格可被本区从多个方向接触，选择威胁时只算一格，但建墙必须分别计算这些边。

全部区域分析完成后，按frontier大小选唯一最大区，将其walls加入总数，再把整个区域标为-1。随后只把其他区此前保存的frontier改为1，不从刚新增的1继续扩散，因此所有区域同步只扩散一层。一个健康格即使也属于被隔离区的frontier，只要仍被其他区威胁，仍会被感染。隔离标记不会重新进入活跃连通块，也不会被未来感染覆盖。

没有活跃区或所有frontier都为空时，已经没有下一夜可扩散的健康格，直接返回累计墙数。外边界没有相邻格，不需要墙；已隔离格也不重复计墙。每个有行动的回合至少永久隔离一个新格，所以至多mn回合。每回合遍历与全部边界合计O(mn)，时间上界O((mn)²)，空间O(mn)；一个健康格最多邻接四个区域，边界集合总量仍线性。原输入保持，不递归遍历长感染区。

独立oracle用并查集重建日初感染组件，再对组件格与所有健康格两两检查曼哈顿邻接，显式收集墙边，最后重建整张下一日快照，不用实现中的区域DFS。枚举1..3行列的682个二值格局，核对所有每个决策日满足唯一最大威胁保证的案例，并核对100个固定种子合法过程；有正威胁并列者排除，不当作原题输入。另核对官方10/4/13墙样例、同一健康格多条墙边、50x50边界与输入保持。未向LeetCode提交。
