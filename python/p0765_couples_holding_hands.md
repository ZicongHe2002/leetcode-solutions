# 765. Couples Holding Hands · Python

[原题](https://leetcode.com/problems/couples-holding-hands/)。

原题2..30对情侣，row为0..2n-1的排列，情侣为(0,1)、(2,3)等。座位固定按(0,1)、(2,3)等相邻两格分组，可交换任意两个人，求让所有情侣同组的最少交换次数。复制row后操作，保留原输入。

先建立每个人当前座位position。逐个处理座位组，第一人的伴侣编号为person异或1。若伴侣已在相邻位，不操作；否则把伴侣与相邻位的人交换，随后同时更新被交换两人的position。每次最多一次交换就固定当前组，后续不会动已固定组：当前第一人的伴侣不可能在先前已经成对的组中。

最少性可用情侣图证明。把每对情侣看作一个顶点，每个座位组把坐在一起的两人的情侣顶点连成一条边，自环表示已配对。每个情侣顶点有两个人，故度为2（自环计两次），每个连通分量是一条允许重边的环；大小m的分量至少要m-1次交换才能拆成m个自环，因为一次交换重接两条边最多增加一个连通分量。

对尚未配好的当前组，其两个不同情侣顶点处于同一环；把第一人的伴侣换过来，恰拆出该情侣自环，并把剩余人员接回一个更短的环。每次交换都让连通分量增加1，最终达到每个情侣一分量，次数等于n减初始分量数，正好达到下界。因此固定每组的贪心全局最优，而不只是构造某个可行排列。

建位置表与扫描时间O(n)，每次交换和两次表更新O(1)，复制及位置表额外空间O(n)。不按排列空间枚举生产解。

独立oracle枚举全部已配对目标排列作为BFS多源起点，以任意两个座位的真实交换为边，求所有排列距合法目标的最短距离，不复用贪心或情侣图公式。2/3/4对情侣全部41064个排列逐个核对。另核对官方例、30对已配对、所有情侣形成一个30环时需29次交换与输入保持。未向LeetCode提交。
