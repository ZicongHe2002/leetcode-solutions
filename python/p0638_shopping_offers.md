# 638. Shopping Offers · Python

[原题](https://leetcode.com/problems/shopping-offers/)。

原题有1..6种商品，单价和需求数量均为0..10，套餐1..100项，每项包含各商品数量及套餐价，分量0..50。每个套餐至少含一件商品，可重复使用，但不能超过任何需求数量；必须恰好满足需求。实现保留price、special和needs，价格为0与需求为0都合法。

先排除在初始需求下已经超量的套餐，因为剩余需求只会减少；再排除不比逐件买便宜的套餐，因为用同样商品的单买替代不会增加花费，也不会影响其他套餐的可用性。这两种筛选不要求套餐唯一，不会删除真正有利的零价套餐。

状态remaining是各商品尚缺数量的不可变元组。用全部单买的价格作为必定可行的上界，再枚举一个不超量的套餐，尝试套餐价+新状态最优价。任何可行购买方案要么没有套餐，要么可移出其中一个套餐并落到更小的状态，因此这些转移覆盖所有方案。套餐至少消耗一件，需求总和最多60，递归严格前进且深度有界；相同剩余需求只求一次。若某套餐价已经不低于当前best，非负的后续花费不可能改善它，可跳过。缓存只属于本次调用，不串用其他商品价格。

设n为商品数、m为原套餐数、S=prod(needs[i]+1)、h=sum(needs)，预处理O(mn)，搜索上界O(Smn)，缓存键及状态共O(Sn)，递归工作O(hn)，另存套餐O(mn)；实际只访问可达状态。不把指数状态数误写成仅O(nm)，也不声称已测完所有最大状态组合。

独立oracle按套餐下标枚举每个套餐的使用次数，再把剩余商品全部单买，不使用按需求缓存的转移。完整覆盖3420个一维双套餐案例和7560个二维双套餐案例，共10980次；另有100个固定种子多维样本。边界覆盖6维、100个套餐、需求10、初始超量套餐、零价单品/套餐及输入保持；大边界使用有独立答案的结构，不穷举最大状态空间。未向LeetCode提交。
