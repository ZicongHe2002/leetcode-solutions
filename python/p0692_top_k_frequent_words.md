# 692. Top K Frequent Words · Python

[原题](https://leetcode.com/problems/top-k-frequent-words/)。

原题words长度1..500，词长1..10且仅小写字母，1<=k<=不同词数。返回前k个词：先按频次降序，频次相等按字典序升序。不能用首次出现顺序替代并列规则，输入保持，输出为str列表。

Counter先统计每个不同词的频次。大小至多k的小根堆需要把当前最差候选放在根：频次越小越差，频次相同时字典序越大越差。因此_Entry的比较先比较频次升序，再比较词的反向字典序。这里堆内顺序与最终输出顺序不同，不能直接把堆数组当答案。

堆尚未满时直接加入；满后把新候选加入并弹出最差项。归纳可知每处理一个不同词，堆都包含迄今最优的k个（不足k时全部），所以遍历完只剩全局前k。最后只对这k项按频次降序、词字典序升序排序，再提取词。

设N为输入词数、U为不同词数、L为最大词长。计数平均哈希成本O(NL)，堆选择和最终排序总计O(U*L*log(k+1))上界，额外空间O(U+k)个词引用和计数；原题L<=10时符合O(N log(k+1))时间、O(N)空间的进阶方向。使用log(k+1)包括k=1时仍需线性扫描，不声称零成本。

独立oracle对每个词用输入列表count求频次，再通过与其他不同词逐一比较计算完整排名，不使用堆、Counter或同一个排序key。a/b/aa/ab构成长度1..6的5460个数组，每个检查全部合法k；另覆盖500个不同的10字符词、k=1/500、频次并列与词前缀顺序、200/200/100三组频次，核对输入保持。未向LeetCode提交。
