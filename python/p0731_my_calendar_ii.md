# 731. My Calendar II · Python

[原题](https://leetcode.com/problems/my-calendar-ii/)。

原题最多1000次book，端点0<=startTime<endTime<=10^9。允许同一时刻被两个预约覆盖，禁止三个预约共同覆盖非空时间段。半开端点相接不构成共同时间；失败返回False并且不得加入预约。

events记录全部已接受预约，doubled记录已有预约两两的非空交集。加入新区间之前，先扫描doubled：若新区间与任何已有双重覆盖区间有非空交集，就会出现三重覆盖，立即拒绝。这个阶段没有修改任何列表，失败不需要事后回滚。

若检查通过，则新区间与每个已有预约的非空交集都可以加入doubled，最后把新区间加入events。三重覆盖若出现，必含新区间和两个旧预约，其共同时间必在某个旧doubled中，早已被第一阶段拒绝，因此不会漏检。反过来命中doubled就确实存在三个预约共同覆盖，不会误拒绝。重叠判断用max(起点)<min(终点)，严格小于保留半开语义。

在合法状态中，两个不同的两两交集不能内部重叠，否则那里至少有三个原预约。每个交集的端点来自已有预约端点，最多2q种端点，彼此内部不交的非空交集数量因此为O(q)。所以每次book扫描两张O(q)列表，时间O(q+1)，Q次总时间O(Q²)，空间O(Q)；不用枚举10^9时间轴。这个空间界依赖合法状态禁止三重覆盖，并非任意区间对都只有线性数量。

独立oracle尝试加入区间后，聚合全部起止端点增量并排序，累计扫描得到最大覆盖深度；超过2就丢弃尝试，不维护两两交集。对0..4端点的10种区间，枚举长度1..4全部11110程序/43210调用，另核对官方程序、同一区间两次成功第三次失败、失败后可相接预约、1000次双重成功及两个满域成功后998次拒绝。未向LeetCode提交。
