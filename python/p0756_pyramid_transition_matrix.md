# 756. Pyramid Transition Matrix · Python

[原题](https://leetcode.com/problems/pyramid-transition-matrix/)。

原题bottom长度2..6，字符来自A..F；allowed最多216个互异三字符规则。规则XYZ表示下层相邻X、Y可托起上层Z，左右不能交换。判断能否从bottom逐层搭到一个字符，输入保持。

先把规则按有序二字符底座分组。对完整当前行row，逐对收集其上方可选字符，再枚举这些位置选择的笛卡尔积，每个组合才是一个完整上层。任何位置没有规则时积为空，当前行失败；行长为1时成功。cache以完整行字符串为键，同一层状态不重复展开。

不能只记录每个位置可能出现的字符集合并在后面任意组合，因为同一层相邻字符的选择可能来自不同的下层组合，混合后会制造不存在的金字塔。这里一次递归固定整行，枚举每个真实允许的直接上层，故成功路径必然逐层满足全部规则；反过来任意合法金字塔的每层都在对应笛卡尔积中，搜索不会漏掉它。

搜索最坏仍为指数级。设处理到的不同行集合为R，行r的各底座选择数乘积为P(r)，某处无选择时P(r)=0；枚举及拼接代价上界O(sum_r len(r)*(1+P(r)))。若字母数为K、底长n，一个较宽松的统一上界为O(n^2*K^(2n-1))，另加读入规则O(|allowed|)；不是多项式DP。缓存字符串总长为O(sum_r len(r))，递归枚举活动状态至多O(n^2)，另存规则O(|allowed|)。原题n<=6、K<=6。

独立oracle直接枚举二字符字母表上所有非底层格子的完整赋值，给每座具体金字塔计算必需规则位掩码；再检查给定规则集是否包含某个完整赋值的全部规则，不使用逐行搜索或记忆表。二字符全部256规则集、长度2..4全部28个bottom，共7168查询。另核对官方可行/不可行例、长度6、空规则、216条规则以及F字符边界。未向LeetCode提交。
