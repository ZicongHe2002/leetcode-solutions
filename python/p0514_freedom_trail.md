# 514. Freedom Trail · Python

[原题](https://leetcode.com/problems/freedom-trail/)。

圆环ring起始下标0对准指针，每转一个位置花1步，可以顺时针或逆时针；对准所需字母后按键另花1步。依次拼出key，求最小总步数。原题两字符串长度1..100、仅小写字母，并保证key中的字母都能在ring中找到。ring保持非空，空key额外返回0。

预先按字母保存环上的全部位置。costs[current]表示已经拼完当前key前缀、环停在current时的最少成本，初始只有0位置/0成本。下一字母可能有多个target位置，不能贪心只留下当前最近的一个；不同位置会影响后续字母的转动成本。

固定current到target，环上最短转动是两方向距离的较小值min(abs(target-current),N-abs(target-current))。对每个target枚举全部旧位置取最小，再加一次按键。新字典完整构造后才替换旧costs，因此不会在同一字母步骤混入新状态。每轮状态只保留当前字母的位置，其余历史只通过最优成本传递。

同一当前位置和已拼前缀具有完全相同的后续选择，保留其中最小成本不会丢失最优解；枚举所有字母位置和所有前驱又覆盖了全部可行路线。最后任意结束位置均可，取最小成本。重复相同字母仍需每次按键，不能把按键次数省掉。

设环长N、key长M，预处理O(N)，每个字母最多N个目标与N个前驱，总时间上界O(N+M*N^2)，位置表和两轮状态共O(N)辅助空间，不保存完整搜索路径。

独立参考以(环下标,已拼字符数)为状态，把左转、右转、合法按键各视为1步做BFS，不使用直接环距离或逐字母最小化。a/b环长1..5、所有可拼key长0..5共3336组对照，空key为扩展。另测环/key各100长、相同字母、反向近路、交替按键、godding与三字母环，核对int，未向LeetCode提交。
