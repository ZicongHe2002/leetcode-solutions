# 650. 2 Keys Keyboard · Python

[原题](https://leetcode.com/problems/2-keys-keyboard/)。

原题从屏幕上一个A与空剪贴板开始，每步只能Copy All或Paste，求恰好得到n个A的最少操作数，1<=n<=1000。复制整个屏幕只花一步；这与4 Keys Keyboard中全选再复制需要两步不同。n=1不做操作，返回0。

去掉没有效果的复制、空剪贴板粘贴及最后一次无粘贴的复制后，程序可分成若干组：复制当前全部内容，然后粘贴f-1次，使字符数乘以f、花费f步，f>=2。最终各组乘数的乘积为n。若一个乘数为合数a*b，改成先乘a再乘b，花费a+b<=a*b，不会增加步数。因此逐层拆到质数就能取得最小总花费，即n的所有质因子之和，重复因子按次数计。

实现试除factor，并在可整除时持续移除该因子、加入步数。每轮只需试到factor²<=当前剩余n；循环结束若还剩大于1的数，它必为质因子，直接加入。最坏时间O(sqrt(原n))、额外空间O(1)，没有建立n项DP表，整数参数的本地更新不影响调用方。

独立oracle在(屏幕字符数,剪贴板字符数)状态图中逐步BFS，真实执行Copy All与非空Paste，不使用乘数分组或质因数。只保留屏幕<=1000的状态：字符数不可减少，超过目标后无法回到目标，故该限制不会删除任何1..1000目标的最优程序。一次BFS给出整个有效输入域的最短距离，再逐一核对全部1000个n及返回类型。未向LeetCode提交。
