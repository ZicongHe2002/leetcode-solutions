# 582. Kill Process · Python

[原题](https://leetcode.com/problems/kill-process/)。

pid与ppid长度相同，1..50000个进程构成一棵有根树。pid唯一且在1..50000，ppid=0的进程恰有一个，0表示根无父亲而不是一个实际进程。kill保证在pid中。终止kill以及全部后代，返回ID列表，顺序任意。输入下标顺序不保证父在子之前，也不能把ID当成数组下标；两输入保持。

先把每个(parent,process)加入children[parent]。然后从kill出发显式深度优先遍历，每弹出一个进程，将其计入结果并压入它的直接孩子。对树深度归纳，kill先计入，每个后代通过唯一父边被发现，其他分支永远不会从kill到达。树无环且每个非根节点仅一个父亲，所以不需要额外visited，结果中每个进程恰好一次。

映射中children[0]保留根进程，但遍历从正数kill开始，沿孩子方向只会遇到真实pid，不把0加入结果。显式栈避免50000层单链触发递归深度限制。先完整建图，避免输入中孩子先出现时丢关系。

建图O(N)，若有K个被终止进程，遍历O(K)，整体时间O(N)，平均哈希模型下成立。邻接表O(N)，待处理栈最坏O(N)，结果O(K)；空间不能因只访问某个小子树就把建图成本遗漏。当前返回深度优先顺序，调用者只应依赖集合正确性。

独立oracle对每个进程沿父链向上追踪，判断是否经过kill，不建孩子邻接表。枚举1..8节点且每个非根父索引小于其子索引的全部5914棵树，反向重标号到接近50000的ID并反转输入记录顺序，逐个kill共46233次比较。另测50000深链、50000节点星形、根/中间/叶子及原题非排序样例，检查无重复、整数ID和输入保持。未向LeetCode提交。
