# 609. Find Duplicate File in System · Python

[原题](https://leetcode.com/problems/find-duplicate-file-in-system/)。

paths给出每个唯一目录及其中所有文件的编码行，目录与各文件项以单个空格分隔，文件项为name(content)。最多20000行，每行最多3000字符，总长最多500000；同目录内名字不重复。按完整内容相同返回至少两个文件的全部路径组，组内及组间顺序任意。不同目录中的同名文件不必相同，不同名字也可以重复内容。只处理题目给定的合法编码，不访问本机文件系统。

拆出目录后，对每个文件项找第一个左括号，以其前缀为文件名、去掉最外层末尾右括号后的中间文本为内容。内容字符串本身作为字典键，分组保存(目录,文件名)对。最后只对组大小至少2者拼接完整路径，单文件组不返回，也不提前给它们分配重复的目录前缀字符串。

处理任意输入前缀后，by_content[c]恰好含已经见过的全部内容为c的文件。新项只进入其精确内容键的组，归纳保证不漏组或混组。字典内部即使发生哈希碰撞，Python仍会核对完整字符串相等，正确性不依赖“短摘要不碰撞”的假设。输入行和字符串不改写。

设输入字符总数为T、返回完整路径字符总数为R。平均哈希模型下，拆分、内容切片和哈希总O(T)，仅在输出阶段拼接实际返回路径，总时间O(T+R)。存储内容键、目录/文件名片段与文件对，加上返回字符串，额外空间O(T+R)。路径目录可能被很多返回文件重复引用，R应单独计入，不能只以编码输入长度掩盖完整路径输出成本。

题目后续的真实文件系统讨论：遍历目录既可DFS也可BFS，前者待处理量通常随深度、后者随宽度，但两者都要检查所有文件元数据。GB内容先按大小筛选，再用固定大小块计算强摘要，仅把大小和摘要相同者列为候选，最后逐块比较原始字节确认，不能因摘要相同就宣称内容相同。若每次只能读1KB，就复用1KB缓冲区完成摘要和确认；摘要读取总字节量为B、实际确认比对量为V时，内容处理O(B+V)，元数据管理另计O(文件数)。磁盘读取通常是主要成本，内容缓冲可保持常数空间，文件索引仍随文件数增长。这是方法说明，本实现未遍历真实磁盘或测量I/O性能。

独立oracle直接使用生成编码前的(完整路径,内容)原始记录，按逐文件内容比较找等价组，不再解析编码，也不使用字典内容分组。4种内容、1..6文件及同目录/各独立目录/交替两目录三布局，共16380组。另核对20000目录、3000字符单行、同名不同内容、不同名相同内容、内容标点和样例；检查组至少2、无重复路径及输入保持。未向LeetCode提交。
