# 729. My Calendar I · Python

[原题](https://leetcode.com/problems/my-calendar-i/)。

原题最多1000次book，0<=startTime<endTime<=10^9。只有新半开区间[startTime,endTime)不会与任何已有预约重叠时才能加入；失败返回False且状态保持。相邻端点相等可以预约，重复预约则冲突。

events按(start,end)排序，并始终只含互不重叠的已接受预约。二分找到新预约的插入位置，只需核对紧前与紧后两个邻居：前驱结束若大于新起点则冲突，后继起点若小于新终点则冲突；等号没有共享时间。其他更早的预约结束不晚于前驱起点，其他更晚的预约起点不早于后继终点，因此不会绕过邻居而与新区间重叠。

两项检查都通过后才insert，失败路径没有任何写入，保持已接受集合不变；成功则仍按顺序且无重叠。初始空表自然满足不变量，归纳覆盖任意合法请求序列。

设q为目前已接受预约数，二分O(log(q+1))，但Python列表插入可能搬移q项，所以每次book最坏O(q+1)，1000次总时间O(Q²)，存储O(Q)。不把二分位置查找冒充整次预约的对数复杂度；不展开10^9时间轴。

独立oracle对小整数端点直接标记每个单位时间槽，任何槽已占用就拒绝，否则占用全部请求槽。对端点0..4的10种非空区间，枚举长度1..4全部11110个请求程序，共43210次book；每次都核对bool返回，后续请求能检测失败是否污染状态。另覆盖1000次成功、满域后999次拒绝、0/10^9与相接端点及官方样例。未向LeetCode提交。
