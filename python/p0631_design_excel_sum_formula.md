# 631. Design Excel Sum Formula · Python

[原题](https://leetcode.com/problems/design-excel-sum-formula/)。

本题接口是Excel(height,width)、set(row,column,val)、get(row,column)、sum(row,column,numbers)，不是Solution。原题高1..26、列A..Z，调用坐标有效，set值在-100..100，每次公式含1..5个单元格或左上到右下的闭矩形引用；至多100次公开操作，并保证没有循环依赖。未赋值格为0。构造器按稀疏字典实现零矩阵，尺寸参数作为有效输入合同，不分配所有零格。

_values只保存常量，_formulas把每个公式格映射到引用格及其次数。单格引用按相同起终点处理；多位行号通过[1:]完整解析。矩形闭区间逐格展开，Counter累加重叠区域与重复单格的次数，不能用集合去重。set删除目标旧公式，sum替换目标旧公式并清除旧常量；其他格继续引用目标本身，因此覆盖后会自然读到新值。

get在依赖DAG上按需计算，memo只活在当前查询中。每个访问格至多计算一次，共享依赖不会反复展开；下一次get重新求值，所以底层常量或公式更新后不会返回过期缓存。sum保存引用关系后调用get返回当前值，并非只保存一次求和的快照。无环由题目保证；路径中每个公式格都需要一次历史sum，在最多100次操作内递归深度有界，不承诺支持任意深的额外输入。

设本次查询可达V个格与E条不同引用边，get时间O(V+E)、临时空间O(V)，重复引用以计数乘法处理；数字按题目整数运算计。若新公式展开含R个格出现，sum构造及求值为O(R+Uold+V+E)，Uold为覆盖旧公式时需释放的不同引用数。set除更新字典外也可能释放旧公式，时间O(1+Uold)。持久空间为已保存常量/公式格及不同引用边总量，不声称每次查询O(1)。

独立oracle把所有格按行优先顺序立即重算，公式用保留重复项的列表和正则解析；生成测试只向更早的格引用，因此无环且可直接顺序求值，不使用生产递归或Counter。50个独立工作簿各执行100次固定种子操作，共5000次API操作，涵盖常量、公式覆盖及后续读取。另覆盖矩形交叠、5次重复引用、负值、公式覆盖常量/常量覆盖公式、多位行号和最大Z26坐标；97格依赖链含98条赋值操作及一次读取，共99次公开操作，检查底层修改传播。测试未向LeetCode提交。
