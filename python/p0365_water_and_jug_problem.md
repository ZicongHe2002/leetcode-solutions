# 365. Water and Jug Problem · Python

[原题](https://leetcode.com/problems/water-and-jug-problem/)。

容量为x与y的两壶可反复装满、倒空，或互相倒到一方空/另一方满，判断能否使一壶或两壶合计恰好有target水。原题x、y、target均在1..1000000。实现额外支持非负容量及target=0；不接受负值。

目标超过总容量x+y时不可能。设g=gcd(x,y)，从全空出发，装满、倒空及倒水都会使各壶水量保持为g的倍数，所以target必须被g整除。反过来，重复装满一壶并向另一壶倒水、满时倒空，会依次产生按容量取模的余量；欧几里得算法给出的g及其合法倍数都可在容量限制内获得。结合允许两壶合计计量，0..x+y范围内g的倍数均可达。因此容量界与整除条件合起来充分且必要。

先处理target=0，也使两壶都为0的扩展不会求模除0；两壶都为0而目标为正时会被总容量界拒绝。没有把目标限制为单壶最大容量，例如x=3、y=5、target=8可以装满两壶。

欧几里得算法时间O(log min(x,y))，固定数量整数占O(1)辅助空间；没有枚举全部容量组合，百万级容量可直接判断。零容量扩展中的gcd同样有定义，前述分支避免g=0的求模。

独立oracle从(0,0)出发，BFS枚举实际填充、倒空、两个方向转移后的水量状态，在任一壶或总水量等于目标时接受，不使用gcd。x/y各0..8、target从0到x+y+2共891项查询对照；0容量/0目标是扩展。另测百万容量、互质/非互质与目标超过总容量。未向LeetCode提交。
