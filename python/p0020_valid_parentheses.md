# 20. Valid Parentheses · Python

[原题](https://leetcode.com/problems/valid-parentheses/)判断三类括号能否按类型和嵌套顺序正确配对。使用`Solution.isValid`，栈保存已经读到但尚未匹配的左括号。

左括号入栈；右括号只能与栈顶配对。栈为空说明右括号过早出现，类型不符说明嵌套顺序错误，都立即返回False。读完后，栈为空才表示没有遗留左括号。例如`([)]`左右括号数量相同，但遇到`)`时栈顶为`[`，所以不合法；计数器无法表达这种嵌套关系。

每个字符最多入栈和出栈一次，时间O(n)，最坏额外空间O(n)。空字符串自然返回True；不属于原题六种括号的字符返回False，避免把任意字符当成右括号。局部状态每次调用重新创建，不跨用例保留栈。

测试覆盖串联、嵌套、交叉、过早闭合、未闭合与非括号字符；实际运行结果写在PR中。没有LeetCode Accepted记录。A实现，OpenAI Codex辅助整理。

## B补写：数量相等仍可能错误嵌套

`{(})`中每种左右括号的数量相同，但不是合法括号串。按栈底到栈顶记状态：

| 下标/字符 | 处理前栈 | 动作 |
| --- | --- | --- |
| 0 / `{` | `[]` | 入栈，得到`['{']` |
| 1 / `(` | `['{']` | 入栈，得到`['{','(']` |
| 2 / `}` | `['{','(']` | 要求栈顶为`{`，实际弹出`(`，立即False |

失败后下标3无需继续处理；若跳过栈顶而在更早位置寻找`{`，就会错误允许括号交叉。这里的短路顺序也保证空栈时不会执行`pop()`。

失败路径可能已弹出一个元素，但栈是该次调用的局部变量，因此不会污染下一次调用。同一`Solution`依次处理`{(})`、`{()}`、`(`、`[]`应依次得到False、True、False、True；第二次调用从空栈开始。B补写此状态推演与调用隔离解释，运行记录见PR。
