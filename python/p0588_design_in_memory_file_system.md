# 588. Design In-Memory File System · Python

[原题](https://leetcode.com/problems/design-in-memory-file-system/)。

实现LeetCode的FileSystem类，包含ls、mkdir、addContentToFile和readContentFromFile四个方法。绝对路径长1..100，除根/以外不以/结束，名字只含小写字母且同目录不重名。所有调用合法：读取和列出目标已存在，写文件的父目录已存在，不会把文件当目录走。mkdir需要补齐缺失中间目录；文件已存在时追加内容，每段长1..50，最多300次公开方法调用。仅模拟内存，不接触本机磁盘。

每个目录节点只有名字到孩子节点的字典，每个文件节点只有按写入顺序保存的内容块列表。两类节点分开，不会把空文件误当成空目录，也没有目录内容与文件内容共用状态。根初始为空目录，/拆分为零个路径分量，从根开始解析即返回根本身。

mkdir逐级查字典，仅为缺失名字创建目录，已有公共前缀继续复用。写文件先解析父目录，最后一个分量作为文件名；文件缺失则创建，存在则把新块追加到列表，保留旧块顺序。读取时join所有块，因此写入不会反复复制整个旧字符串。ls若解析到文件就仅返回它的最后一级名字，否则排序返回该目录直接孩子的名字，不包含更深后代的路径。每次返回新的列表，调用者修改列表不会修改文件树。

路径分量唯一确定从根出发的节点，对分量数归纳，解析每次都到达正确的直属孩子。mkdir保持此前节点与内容；写入仅改变一个文件的末尾块；读取和ls不创建节点或改变状态。每个FileSystem实例独立持有根，不共享全局字典。

设路径字符数为L，目录孩子数为D，名字最大长S，目标文件内容总长C。平均哈希查找下解析与mkdir为O(L)；追加为O(L)路径解析加一次摊销O(1)列表追加，保存传入的不可变字符串引用，不复制旧内容。读取O(L+C)。ls目录的排序比较成本上界O(L+D log D*S)，返回文件为O(L)。总存储为所有名字字符、内容字符及节点/内容块引用的线性量，临时路径拆分O(L)，目录输出列表O(D)。这些界限不声称单次列表扩容为最坏常数。

独立参考模型使用完整路径目录集合和文件字符串字典，不遍历节点，目录列举按字符串前缀找直属名字，追加直接拼接字符串。100个固定种子，每个实例恰300次合法操作，共30000次逐步对照；最后50次专门读取和列举，以核对早先写入。另测空根、多级mkdir、字典序、文件ls、返回列表隔离、实例隔离，以及长度100路径和297次50字符追加（该实例总300次调用）。未向LeetCode提交。
