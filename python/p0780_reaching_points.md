# 780. Reaching Points · Python

[原题](https://leetcode.com/problems/reaching-points/)。

原题四个坐标均为1..10^9，正向一步可把(x,y)变为(x+y,y)或(x,x+y)。判断起点能否到达目标，零步允许。不向左下移动，不使用减法生成正向边。

逆向时较大坐标必是上一步加出来的坐标，因为所有坐标始终正数；如x>y，唯一正父状态为(x-y,y)。连续相减相同y可用x%=y批量完成，只要当前两个坐标都仍大于各自起点，就继续对较大者取余。

批处理不会跳过一个可达的起点边界。以固定y>sy为例，若起点sx>=y，则从(sx,sy)保持x=sx并把y第一次增大，至少得到sy+sx>sx>=y，已超过当前y；而一旦x增大又不可能退回sx。因此在这种情况下，中途遇到x=sx也不能是可达路径。若sx<y，批处理落到的余数就是该减法链中唯一可能等于sx的值。对另一坐标同理；取余为0时也不可能继续匹配正起点。

循环结束后若x恰为sx，后续正向只能保持x不动、重复给y加sx，所以须有y>=sy且差能整除sx；若y恰为sy则对称处理。两坐标都匹配时差0，自然包含零步；一坐标已低于起点而另一也不匹配则拒绝。起点正数保证最后的除数非0。

欧几里得余数过程时间O(log(max(tx,ty)))，额外空间O(1)，在原题有界整数范围内算术精确。不按可能高达10^9的单步次数枚举减法。

独立oracle对每个1..5小起点，只执行真实正向加法边，枚举坐标都不超过30的完整可达图，再核对1..30全部目标，共22500查询。坐标只增不减，任何到该小目标的路径都不会先越界再返回，因此有界图覆盖这些查询的所有可能路径。另核对100条固定种子实际正向路径、10^9、边界整除、坐标相等及目标更小，检查bool。未向LeetCode提交。
