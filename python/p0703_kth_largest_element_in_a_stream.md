# 703. Kth Largest Element in a Stream · Python

[原题](https://leetcode.com/problems/kth-largest-element-in-a-stream/)。

原题初始化nums长0..10000，1<=k<=len(nums)+1，初始值与新增值均在-10000..10000，add最多10000次。每次加入后返回全部已见分数按重数排序的第k大，不是第k个不同值。接口为KthLargest(k,nums)/add(val)。构造时可能只有k-1项，第一次真正add后即满足至少k项；构造过程不提前调用公共add，保持调用方nums。

小根堆只保留当前最大的min(k,已见数量)个分数。初始化先取最大的至多k项再建堆；新值到来时，若堆未满就加入，满后加入并弹出最小项。因此每一步之后仍保留全部已见值中的前k大，其最小项恰为第k大。较差新值会立即被弹出；重复值按出现次数占据多个位置，不能先转成集合。

每次真正add后至少k项，堆根必存在且有定义。k=1时只保留最大值；空初始输入只能取k=1，第一次加入后自然返回该值。堆内容独立于调用方列表，没有原地heapify输入。

设初始长度N，初始化时间O((N+1)*log(k+1))上界，单次add为O(log(k+1))，存储O(k)。+1包含N=0与k=1的常数工作；不保留完整历史或每次全排序。

独立oracle在测试端保留完整历史，每次真正插入后重新排序取第k项，不使用堆。三种有符号值的初始长度0..3、全部合法k与长度1..3插入程序共5538个实例、14484次返回值；另核对10000初始分数/10000次add的闭式排名、初始k-1、空输入、重复与正负边界，核对原nums保持。未向LeetCode提交。
