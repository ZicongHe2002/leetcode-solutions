# 465. Optimal Account Balancing · Python

[原题](https://leetcode.com/problems/optimal-account-balancing/)。

给定历史付款[from,to,amount]，允许重新安排任意人之间的结算，求使所有净余额归零的最少转账次数。原题1..8笔交易，人员编号0..11，付款人与收款人不同，每笔金额1..100。原输入保持；空交易额外返回0。

先按人汇总净余额，去掉已为0的人。剩余m<=12个余额总和为0。任一结算方案的每个连通分量都必须内部净额为0，含t个非零余额的人至少需要t-1条转账边。反过来，一个零和组可以通过不断匹配付款方与收款方，在至多t-1次中清零。因此若最多能划成g个非空零和组，最少次数恰为m-g；净额为0的人无需作为中转参与。

枚举余额的一种排列，每当累计前缀和为0，就能结束一个零和组。全部零和分组都可以把各组依次排列得到，所以最大分组数等于所有排列中零和前缀的最大个数。用mask表示已经排入前缀的人，totals[mask]是前缀和；最后一个人可以是mask中的任意一位，故groups[mask]=max(groups[mask去掉该位])+(totals[mask]==0)。选择顺序通过子集DP完整覆盖，没有按金额大小贪心配对。

汇总O(T)，子集DP有2^m状态，每状态枚举至多m位，总时间O(T+m*2^m)，辅助空间O(2^m+m)。m=0时两个数组只有空状态，直接得到0。生产不会枚举所有转账金额或递归重试结算路径。

独立参考取第一个非零余额，枚举与每个相反符号余额结算的选择，再递归搜索最少支付次数，不使用零和前缀DP。四个人、金额1/2、长度1..3的全部14424段交易序列核对。另测12个非零参与者、8笔交易/100金额上界、完全抵消、长链净额合并与无真零和子组的例子，检查输入保持；空交易为扩展。未向LeetCode提交。
